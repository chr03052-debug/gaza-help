# Security policy

## Report a security or safety issue

Use GitHub's private **Report a vulnerability** feature in the repository Security tab when the report could expose users, reveal sensitive information, enable tracking, or describe an exploitable technical weakness.

Do not post names, phone numbers, precise locations, case details, credentials, or other sensitive information in a public issue.

For public, non-sensitive corrections, use the repository issue forms.

## What to report

- incorrect or disputed emergency, protection, health, food, water, or shelter information;
- personal or sensitive location data;
- unsafe referral or movement guidance;
- privacy, tracking, authentication, content-injection, or offline-cache problems;
- an official source that changed, disappeared, or contradicts the site.

## Response targets

- Critical safety issue: unpublish or neutralize the affected claim as soon as it is confirmed, before investigating improvements.
- High-risk incorrect contact or route: remove the specific detail and link to the official source.
- Broken or changed source: mark the record for manual review and avoid asserting current availability.
- Technical issue without immediate user risk: fix through a reviewed pull request.

No report should be treated as resolved until the published site has been checked.
